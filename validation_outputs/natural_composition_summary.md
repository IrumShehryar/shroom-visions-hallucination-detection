# Natural-Composition Confirmation of the Sonnet Mischaracterization Filter

Generated by `src/verify_natural_composition.py`. Full per-case detail (id, span,
gold labels, verdict, reason) is in `verify_natural_composition_results.json`
(60 entries). This file is the summary that only existed in console scrollback.

## Why this run exists

The prior 51-sample verification (`mischar_verification_full_case_log.md`) used
curated batches, hand-balanced ~50/50 FP/TP. That's useful for measuring catch
rate and FN rate cleanly, but it doesn't tell you what happens if you point the
filter at the pipeline's *actual* output distribution. This run draws a plain
random sample from that real distribution instead.

## Natural population (current pipeline, post numeral-fix, no API calls needed)

Every mischaracterization flag the pipeline currently emits, across the 325
gold-checked rows where raw Haiku reasoning is available (286 dev + 39 fresh
held-out):

| | count | % |
|---|---|---|
| Total mischaracterization flags | 134 | 100% |
| TP (overlaps a gold mischaracterization span) | 43 | 32.1% |
| FP (no gold mischaracterization overlap) | 91 | 67.9% |

**This is much noisier than the curated 50/50 batches implied** — roughly 2 in 3
mischaracterization flags the pipeline produces are false positives in the wild.

## The 60-sample random draw

Drawn from the full 134-flag pool (not the post-exclusion remainder, which would
have been skewed toward FPs after the curated batches used up most known TPs).
20 of the 60 happened to already have a cached verdict from prior batches (reused,
no charge); 40 required a fresh Sonnet call.

| | count | % |
|---|---|---|
| Sample size | 60 | — |
| TP in sample | 24 | 40.0% |
| FP in sample | 36 | 60.0% |

(Sample composition skews slightly TP-heavy vs. the true 32/68 population split —
expected sampling noise at n=60, not a methodology issue.)

## Catch rate / FN rate on the natural draw

| Metric | Value |
|---|---|
| Catch rate (natural FPs correctly rejected) | 12/36 = **33.3%** |
| FN rate (natural TPs wrongly rejected) | 4/24 = **16.7%** |
| Parse errors (reused, excluded from rate calc) | 2 |

Catch rate is notably **lower** than the curated batches suggested (which ran
70-95% depending on batch). FN rate is consistent with the curated-batch range
(~15-20%).

## Real scorer effect (the actual confirmation)

Applied the official scorer's `score_cor` / `score_cor_lbl` before vs. after the
drop-on-reject filter, isolated to the mischaracterization spans on the 55
touched rows (2 image-missing rows dropped, some ids repeated across multiple
flags):

| Metric | Before | After | Delta |
|---|---|---|---|
| Cor | 0.1824 | 0.2683 | **+0.0859** |
| Cor+Lbl | 0.1344 | 0.2215 | **+0.0871** |

**Net positive, despite the lower catch rate** — because natural FPs outnumber
natural TPs roughly 2:1, catching even a third of them still removes more noise
than the occasional wrongly-dropped true flag costs.

## Cost

40 fresh Sonnet calls: input=90,186 tokens, output=3,702 tokens, **$0.2174**.

## Bottom line

The curated-batch result held up under a genuinely random draw from the pipeline's
real output distribution. The filter is now implemented as an actual pipeline step
(`src/verify_mischaracterization.py`, wired into `src/span_mapper.py` and
`src/generate_test_predictions.py` behind `ENABLE_SONNET_VERIFICATION`, default
`False`). Estimated full-test-set cost if enabled: ~815 flags × ~$0.0054/call ≈ **$4.40**.
